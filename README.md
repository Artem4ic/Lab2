# Лабораторная работа № 1, задача № 2: N тел

Это рабочая реализация с пояснениями, замерами ноутбука и текстом отчёта.
Результаты замеров на ноутбуке находятся в measurements_windows11/. Используются C11 и POSIX Threads, как в примерах курса.
Структура кода повторяет их подход: объявления структур и прототипов,
`main`, отдельные функции `Get_options`, `Thread_work` и другие,
разделители между функциями, явные выделение и освобождение памяти.

## Файлы и сборка

- `nbody_serial.c` — последовательный алгоритм: сначала читать его.
- `nbody_pthreads.c` — параллельный алгоритм с постоянными рабочими потоками.
- `nbody.c`, `nbody.h` — общие структуры, ввод/вывод и физические формулы.
- `timer.h` — неизменённый заголовок преподавателя.
- `examples/` — два небольших входных файла.
- `tests/test_nbody.py` — независимые проверки, нужен Python 3.

В Linux или Ubuntu в WSL:

```bash
make
./nbody_serial 10 examples/two_bodies.txt 0.01 serial.csv
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel.csv 4
make test
```

Без Make:

```bash
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic nbody_serial.c nbody.c -lm -o nbody_serial
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic -pthread nbody_pthreads.c nbody.c -lm -o nbody_pthreads
```

Интерфейс:

```text
./nbody_serial tend input.txt [dt [output.csv [xy|xyz]]]
./nbody_pthreads tend input.txt [dt [output.csv [threads [xy|xyz]]]]
```

Первые два аргумента соответствуют условию. Дополнительные аргументы
позиционные: чтобы указать более поздний аргумент, нужно указать предыдущие.
По умолчанию: `dt=0.01`, `output.csv=trajectory.csv`, `threads=2`, формат `xy`.
Количество потоков ограничено диапазоном 1–1024 для проверки ввода;
реально разумный выбор зависит от CPU и доступной памяти.
Имя выходного файла должно отличаться от имени входного файла и важных
существующих файлов: CSV открывается с перезаписью.

## Вход и выход

Первая строка — положительное целое N, затем N строк:

```text
mass x y z vx vy vz
```

Требуются конечные числа, масса строго положительна. Числа записываются
с десятичной точкой. Используется согласованная система СИ: килограммы,
метры, секунды; `G = 6.67430e-11`.

В условии есть несогласованность: вход трёхмерный, а формулы и пример CSV
двумерные. Принято следующее явное решение:

- физика всегда рассчитывается в 3D;
- по умолчанию CSV содержит `t,x1,y1,x2,y2,...`, как в условии;
- режим `xyz` сохраняет полные траектории: `t,x1,y1,z1,x2,y2,z2,...`.

Для плоской системы задайте `z=0`, `vz=0` у всех тел.
Ненулевые z влияют на силы даже в режиме вывода `xy`.
Выбор 3D-расчёта с xy-проекцией — наша интерпретация неоднозначности,
а не дополнительное требование преподавателя.

Пример полного вывода:

```bash
./nbody_pthreads 10 examples/two_bodies.txt 0.01 trajectory3d.csv 4 xyz
```

Первая строка файла — заголовок, следующая — состояние при `t=0`.
Последняя строка соответствует `t=tend`. Последний шаг сокращается,
если остаток времени меньше `dt`. Внутри цикла фактический шаг равен
`next_time - time`; из-за округлений double шаги могут немного отличаться
от заданного dt, включая очень короткий последний шаг.

## 1. Последовательный алгоритм

`struct body_s` хранит массу, положение и скорость одного тела.
`struct vector_s` хранит три компоненты вектора.

На каждом шаге:

1. Обнуляем все силы.
2. Обходим только пары `i < j`.
3. Вычисляем силу, действующую на i со стороны j:

   `Fij = G * mi * mj * (rj - ri) / |rj - ri|^3`.

4. Прибавляем её к `forces[i]`, вычитаем из `forces[j]`.
5. Только после завершения ВСЕХ пар обновляем положения и скорости.

Таким образом, на шаге считаем ровно `N*(N-1)/2` взаимодействий,
а не `N*(N-1)`. Противоположны именно силы, а не ускорения:
у тел с разными массами ускорения отличаются.

Явный метод Эйлера, как в методичке:

```text
r_new = r_old + v_old * h
v_new = v_old + (F_old / m) * h
```

`Update_body` сначала изменяет координаты, используя ещё старую скорость,
затем скорость. Силы к этому моменту уже рассчитаны для всей системы,
поэтому обновление координат одного тела не влияет на силы других тел
текущего шага.

Не переставляйте обновление скорости перед обновлением положения:
получится другой метод интегрирования.

## 2. Параллельный алгоритм

Создаём P потоков один раз. У каждого есть свой массив из N векторов сил:
`local_forces[rank][i]`. Во время вычисления сил поток пишет только в свой
массив, но читает общие, пока неизменяемые, положения и массы.

Распределяем строки верхнего треугольника циклически:

```text
поток 0: i = 0, P, 2P, ...
поток 1: i = 1, P+1, 2P+1, ...
...
для каждого назначенного i: j = i+1, ..., N-1
```

Длинные и короткие строки перемежаются между потоками. Это простое
приближённое выравнивание нагрузки, а не строго равное распределение
количества пар. При малом N и большом P дисбаланс заметнее.
Каждая пара всё равно назначена ровно одному потоку, остатки не теряются.

Барьер включает P рабочих потоков и main. Один шаг состоит из трёх встреч:

1. **Старт:** main задаёт фактический шаг; потоки начинают расчёт сил.
2. **Силы готовы:** все локальные массивы заполнены. Теперь разрешено
   менять положения; до этого момента никто их не менял.
3. **Обновление готово:** каждый поток суммировал вклады всех потоков
   для своего диапазона тел и обновил его. Main может записать CSV.

Для обновления тел используются непересекающиеся диапазоны:

```text
first = N * rank / P
end   = N * (rank + 1) / P
```

Каждое тело имеет одного писателя. Рабочие потоки ждут у следующего
стартового барьера, пока main записывает CSV. Поэтому запись не конфликтует
с изменением координат или обнулением локальных массивов.

После последнего шага main устанавливает `stop=1` и проходит стартовый
барьер ещё раз. Потоки видят сигнал и завершаются, main вызывает join.
Обычные общие переменные `current_step` и `stop` здесь защищены порядком
барьеров; добавлять `volatile` не требуется и само по себе от гонок не спасает.

Мьютекс и условная переменная используются только для безопасного старта:
если удалось создать лишь часть потоков, они завершаются до входа в барьер,
вместо ожидания несуществующих участников. В вычислении каждой пары
мьютексов нет. Ожидание условия старта находится в `while`, чтобы учитывать
ложные пробуждения.

`pthread_barrier_wait` возвращает одному участнику
`PTHREAD_BARRIER_SERIAL_THREAD`; это успешное прохождение, а не ошибка.

## Стоимость и ограничения

- Последовательная версия: O(N²) работы на шаг, O(N) дополнительной памяти.
- Параллельная: суммарно O(N² + PN) работы, O(PN) дополнительной памяти.
- Локальные силы: примерно `24 * P * N` байт на типичной системе с
  8-байтовым double. Объединение требует PN вкладов на шаг.
- Нет блокировок на каждой паре; есть расходы барьеров и объединения сил.
- При малом числе тел параллельная версия может быть медленнее.
- Порядок сложения отличается, поэтому результаты разных P могут иметь
  небольшие расхождения из-за округления double. Сравниваем с допуском.
- Это точечная гравитационная модель без столкновений и смягчения силы.
  При совпадении положений во время расчёта сил программа выдаёт ошибку.
  Произвольное epsilon не добавляется: оно изменило бы модель из задания.
- Эйлер первого порядка не сохраняет энергию точно; для длинных траекторий
  и тесных сближений ошибка может быть большой. Следует уменьшать dt и
  проверять сходимость. Значение 0.01 — удобное значение по умолчанию,
  а не универсально подходящий физический шаг.
- Проверяются неконечные силы и состояния, ошибки ввода/вывода и Pthreads.
  При фатальной ошибке процесс завершается; CSV может остаться частичным.
- Реализация рассчитана на Linux/WSL с POSIX barriers.

## Проверки и будущие замеры для отчёта

`make test` проверяет равномерное движение одного тела в 3D, две массы
с аналитически известным результатом первых двух шагов, использование
старой скорости, неподвижность центра масс в симметричном тесте,
несколько случайных 3D-систем и P, не делящее N, а также P>N,
нулевое конечное время, короткий последний шаг, формат xy и неверный ввод.
Эталон в Python независимо суммирует ускорения по всем соседям каждого
тела; это помогает выявить ошибки общей C-функции физики, которые одно
сравнение двух C-версий не обнаружило бы.

Для отчёта нужны повторные замеры на одном компьютере при одинаковых
N, tend, dt и входном файле: последовательный вариант и P=1,2,4,...
Указать CPU, ядра/потоки, ОС, компилятор, флаги, количество повторов и
выбранную статистику, например среднее из 5 запусков.

Программа выводит два разных времени через преподавательский GET_TIME:

- `Compute time`: сумма интервалов вычисления каждого шага, без CSV;
  в параллельной версии включает барьеры и объединение, но не создание/join.
- `Total time`: расчёт с CSV и его закрытием; в параллельной версии также
  включает создание/join потоков. Чтение входа и выделение памяти исключены.

GET_TIME использует gettimeofday, как в примерах преподавателя; часы не
монотонные, а очень короткие интервалы измеряются грубо. Для серьёзного
сравнения берите достаточно большие задачи и несколько запусков.
Ускорение: S=T_serial/T_parallel; эффективность: E=S/P. Сравнивать нужно
одинаковые виды времени. Результаты ноутбука находятся в REPORT.md и measurements_windows11/.
Результаты замеров на ноутбуке находятся в measurements_windows11/.
Описание алгоритмов, методики и результатов — в REPORT.md.
Для защиты прочитайте DEFENSE.md; для Windows 11 — WINDOWS11_WSL2.md.
Повторить серию: python3 tools/benchmark.py --out measurements_local.
