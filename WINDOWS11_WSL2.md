# Запуск на Windows 11 через WSL 2

Команды PowerShell и Ubuntu выполняются в разных окнах. Не вставляйте
все команды этой инструкции сразу. Сначала настройка Windows, затем Linux.
WSL (Windows Subsystem for Linux) — правильное название; на скриншоте
показаны команды для WSL 2.

## 1. Если WSL ещё не установлен

Откройте Пуск → найдите PowerShell → «Запуск от имени администратора».
Выполните:

```powershell
wsl --install -d Ubuntu
```

Перезагрузите ноутбук. Откройте Ubuntu из меню Пуск. Дождитесь первичной
настройки, создайте Linux-имя пользователя латиницей и пароль.
При наборе пароля в Ubuntu символы не отображаются — это нормально.

В PowerShell проверьте:

```powershell
wsl -l -v
```

У Ubuntu должна стоять VERSION 2. Если так и есть, переходите к разделу 3.

## 2. Если Ubuntu уже есть или требуется способ со скриншота

Сначала посмотрите точное имя установленного дистрибутива:

```powershell
wsl -l -v
```

Если VERSION 1, преобразуйте его (пример для имени Ubuntu):

```powershell
wsl --set-version Ubuntu 2
```

Если имя другое, например Ubuntu-24.04, используйте это точное имя вместо
Ubuntu. `wsl --set-default-version 2` задаёт версию для будущих установок,
но само по себе не преобразует уже установленную Ubuntu.

На вашем скриншоте показана ручная активация компонентов Windows.
Если обычная установка не сработала, выполните в PowerShell администратора
каждую команду ОДНОЙ строкой:

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
bcdedit.exe /set hypervisorlaunchtype auto
```

После успешного выполнения перезагрузите Windows. Затем:

```powershell
wsl --update
wsl --set-default-version 2
wsl -l -v
```

Если Ubuntu установлена и показана версия 1:

```powershell
wsl --set-version Ubuntu 2
```

Если Ubuntu отсутствует:

```powershell
wsl --install -d Ubuntu
```

В компонентах Windows на скриншоте используются «Платформа виртуальной
машины» и «Подсистема Windows для Linux». В современной установке часть
настройки выполняет `wsl --install`; ручная последовательность — запасной
вариант, а не обязательное повторение после успешной установки.

Если WSL сообщает, что виртуализация выключена, проверьте Диспетчер задач
→ Производительность → ЦП → «Виртуализация». Если она отключена,
в UEFI/BIOS ноутбука потребуется включить Intel VT-x / Intel Virtualization
Technology или AMD-V / SVM. Конкретное меню зависит от модели ноутбука.

Официальные источники Microsoft, проверены 15.10.2026:

- https://learn.microsoft.com/en-us/windows/wsl/install
- https://learn.microsoft.com/en-us/windows/wsl/install-manual
- https://learn.microsoft.com/en-us/windows/wsl/troubleshooting
- https://learn.microsoft.com/en-us/windows/wsl/filesystems

## 3. Установить инструменты внутри Ubuntu

Откройте Ubuntu через Пуск. Здесь выполняются уже Linux-команды:

```bash
sudo apt update
sudo apt install build-essential python3 unzip
```

`sudo` может запросить пароль Linux, который вы создали при первом запуске.
Для загрузки пакетов потребуется интернет.

## 4. Перенести архив в Ubuntu

Скачайте выданный архив. Для самого простого пути создайте в Windows папку
`C:\lab`, положите архив туда и назовите его `nbody_lab_task2.zip`.
В Ubuntu:

```bash
mkdir -p ~/labs
cd ~/labs
unzip /mnt/c/lab/nbody_lab_task2.zip
cd nbody_lab
```

Внутри `~/labs/nbody_lab` лежат исходники. Архив распаковывается в Linux,
чтобы сборка и замеры не зависели от производительности каталога `/mnt/c`.
Если эта папка уже существует, сначала сохраните собственные изменения:
распаковка обновлённого архива может предложить перезапись.

## 5. Собрать и запустить

Все следующие команды — в Ubuntu, в каталоге `~/labs/nbody_lab`:

```bash
make
make test
./nbody_serial 10 examples/two_bodies.txt 0.01 serial.csv
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel.csv 4
```

Ожидается: успешная компиляция, сообщение OK от тестов, вывод времени,
файлы `serial.csv` и `parallel.csv`. Две траектории могут различаться
в последних цифрах double; программа проверки использует допуск.

Аргументы параллельной программы:

```text
./nbody_pthreads tend input.txt dt output.csv threads xy|xyz
```

- `tend` — физическое время моделирования в секундах, не время работы CPU.
- `input.txt` — начальные массы, координаты и скорости.
- `dt` — шаг интегрирования, также в секундах.
- `output.csv` — имя нового файла результатов.
- `threads` — число рабочих потоков; main дополнительно управляет расчётом.
- `xy` / `xyz` — формат вывода; по умолчанию xy.

Для полной 3D-траектории:

```bash
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel3d.csv 4 xyz
```

Не указывайте входной файл как выходной: выход открывается с перезаписью.

## 6. Повторить замеры на вашем ноутбуке

Подключите питание, закройте тяжёлые приложения; не меняйте настройки
энергопотребления между сериями. В Ubuntu:

```bash
python3 tools/benchmark.py --out measurements_windows11
```

Будут проверены N=128 и N=2048, последовательная программа и P=1,2,4,8.
Один прогрев и пять измерений на конфигурацию. Это несколько десятков
запусков, поэтому дождитесь финального сообщения `All comparisons PASS`.
Скрипт сравнивает все координаты xyz и все моменты времени с последовательным
расчётом; сырые времена и характеристики среды сохраняются автоматически.

Если доступно мало процессоров, можно сократить список, например:

```bash
python3 tools/benchmark.py --out measurements_windows11_p4 --threads 1 2 4
```

Выходная папка должна быть новой для отдельной серии, чтобы не смешивать
старые и новые результаты. `measurements/` в архиве содержит замеры автора
решения на сервере; ваши результаты сохраняйте отдельно. Значения `lscpu`
внутри WSL описывают доступные виртуальные CPU, а не обязательно всю
физическую топологию ноутбука. Для отчёта дополнительно запишите модель
ноутбука и CPU из Windows, объём ОЗУ и режим питания.

Что прислать для окончательного отчёта по ноутбуку: `summary.csv`,
`raw_times.csv`, `comparisons.csv`, `environment.json` из вашей папки замеров.

## 7. Открыть код, пояснения и результаты в Windows

Из папки проекта в Ubuntu:

```bash
explorer.exe .
```

Откроется Проводник Windows с файлами Linux. Файлы `.c`, `.h`, `.py`, `.md`
можно открывать текстовым редактором. Для удобства — установленным VS Code:
откройте папку проекта через WSL и расширение WSL; после настройки команды
`code` обычно можно вызвать `code .` из Ubuntu. VS Code необязателен:
сборка и запуск выше работают в терминале Ubuntu.

Порядок чтения:

1. `README.md` — устройство программы и ограничения.
2. `nbody.h` — структуры тела и вектора, прототипы функций.
3. `nbody_serial.c` — основной цикл и вычисление сил.
4. `nbody.c` — формулы физики, ввод и CSV.
5. `nbody_pthreads.c` — распределение пар, локальные силы и барьеры.
6. `REPORT.md` — текст для отчёта и результаты серверных замеров.
7. `DEFENSE.md` — разбор и вопросы к защите.

`measurements/summary.csv` можно открыть в Excel. Если всё попало в один
столбец: Данные → Из текста/CSV → разделитель «запятая», десятичный
разделитель «точка» (при необходимости выбрать локаль English US).
Для траекторий стройте точечную XY-диаграмму: x1 по горизонтали, y1 по
вертикали; добавьте x2/y2 отдельным рядом. Это проекция на плоскость xy.
Для времени используйте столбец t.

## 8. Частые ошибки

- `make: command not found`: выполните установку build-essential в Ubuntu.
- `No such file or directory`: проверьте `pwd`, затем `ls`; войдите в проект.
- PowerShell не понимает `sudo` или `./nbody_serial`: откройте Ubuntu.
- `pthread.h` не найден в обычном Windows-компиляторе: собирайте в Ubuntu.
- `pthread_create` сообщает об ошибке: уменьшите число потоков.
- `Zero or non-finite distance`: два тела совпали или данные слишком велики;
  проверьте начальные условия и шаг времени. Это не проблема WSL.
- Параллельная версия медленнее: на малой задаче это нормально;
  сравнивайте большие N и несколько повторов, а не один запуск.
