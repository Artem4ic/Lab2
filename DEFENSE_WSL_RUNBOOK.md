## 1. В каких окнах вводятся команды

Используются два разных терминала:

| Окно | Для чего нужно | Какие команды сюда относятся |
|---|---|---|
| **PowerShell в Windows** | Посмотреть установленные дистрибутивы и открыть Linux | `wsl -l -v`, `wsl -d Ubuntu` |
| **Ubuntu под WSL** | Собрать C-программы, запустить их и посмотреть CSV | `cd`, `ls`, `make`, `./nbody_serial`, `python3` |

WSL — подсистема Windows для запуска Linux. Для этой лабораторной достаточно терминала Ubuntu: устанавливать графический рабочий стол Linux не требуется.

В блоках ниже вводи только сами команды. Обозначения приглашения терминала, например `PS C:\...>` или `artem@...:~$`, переписывать не нужно.

В Windows Terminal вставить скопированный текст обычно можно через **Ctrl + Shift + V**. Если вставляется многострочный блок, сначала прочитай его и выполняй по смысловым шагам.

## 2. Как открыть Ubuntu на своём Windows-ноутбуке

### Способ A: через меню «Пуск»

1. Нажми клавишу **Win**.
2. Напечатай **Ubuntu**.
3. Открой установленное приложение Ubuntu.
4. Дождись строки приглашения с Linux-именем пользователя. Теперь можно выполнять команды с пометкой `bash`.

Если видишь строку с именем пользователя и мигающим курсором, Ubuntu уже работает. Отдельное окно с рабочим столом появляться не обязано.

### Способ B: через PowerShell

1. Нажми **Win** и найди **PowerShell** или **Терминал**.
2. Открой обычное окно. Для запуска уже установленного WSL права администратора обычно не нужны.
3. Посмотри названия дистрибутивов:

```powershell
wsl -l -v
```

Пример структуры вывода:

```text
  NAME      STATE      VERSION
* Ubuntu    Stopped    2
```

- `NAME` — точное имя установленного Linux.
- `Stopped` означает, что он сейчас выключен; запуск включит его.
- `VERSION 2` означает WSL 2.
- Звёздочка отмечает дистрибутив по умолчанию.

Если имя — `Ubuntu`, открой его:

```powershell
wsl -d Ubuntu
```

Если в колонке `NAME` написано иначе, подставь именно это имя после `-d`. Название дистрибутива и номер версии Ubuntu — разные вещи: не угадывай имя по версии из отчёта.

После запуска WSL окно может выглядеть почти так же, но команды уже выполняются в Linux. Дальше вводи команды из разделов Ubuntu.

## 3. Один раз до защиты: проверить нужные инструменты

В **Ubuntu** выполни:

```bash
gcc --version
make --version
python3 --version
```

Ожидается информация о версиях, а не `command not found`.

- **GCC** собирает исходники C в исполняемые файлы.
- **Make** выполняет правила из `Makefile`.
- **Python 3** запускает утилиты сравнения и повторных замеров.
- **unzip** понадобится, чтобы распаковать проект.

Если чего-то не хватает, установи инструменты заранее, в Ubuntu:

```bash
sudo apt update
sudo apt install build-essential python3 unzip
```

Для загрузки пакетов нужен интернет. `sudo` попросит пароль пользователя **Linux**, созданный при настройке Ubuntu. Во время ввода пароля символы не показываются — это нормально. Набери пароль и нажми Enter.

На самой защите, если инструменты уже установлены, повторять установку не нужно.

## 4. Один раз до защиты: положить актуальный проект в Linux

Если исходники уже находятся в Linux и программы собираются, можно пользоваться своей папкой. Путь дальше нужно будет заменить на её настоящий путь. Ниже дан один конкретный вариант расположения, чтобы все следующие команды работали одинаково.

### 4.1. Скачать архив в Windows

1. Открой ссылку на актуальную ветку проекта:

   <https://github.com/Artem4ic/Lab2/tree/work>

2. Выбери **Code → Download ZIP**. Можно сразу скачать:

   <https://github.com/Artem4ic/Lab2/archive/refs/heads/work.zip>

3. В Проводнике Windows создай папку **`C:\lab`** и положи туда ZIP.
4. Назови архив **`Lab2-work.zip`**. Например, скачанный `Lab2-work (1).zip` можно переименовать.
5. Для проверки имени включи в Проводнике **Вид → Показать → Расширения имён файлов**. Расширение `.zip` должно быть одно.

### 4.2. Найти этот архив из Ubuntu

В Ubuntu диск Windows `C:` обычно доступен как `/mnt/c`. Проверь файл:

```bash
ls -l /mnt/c/lab/Lab2-work.zip
```

Если показаны имя, размер и дата архива, путь найден. Если появляется `No such file or directory`, сначала проверь расположение и имя архива в Windows.

### 4.3. Распаковать в домашнюю папку Linux

Следующие команды предназначены для первоначальной подготовки новой папки:

```bash
mkdir -p ~/labs &&
mkdir ~/labs/nbody-defense &&
unzip /mnt/c/lab/Lab2-work.zip -d ~/labs/nbody-defense &&
cd ~/labs/nbody-defense/Lab2-work
```

- `~` — домашняя папка твоего пользователя Linux.
- `mkdir -p ~/labs` создаёт общую папку для работ, если её ещё нет.
- `mkdir ~/labs/nbody-defense` создаёт отдельную папку для этой демонстрации.
- `unzip ... -d ...` распаковывает ZIP в указанное место.
- Внутри GitHub-архива есть корневая папка `Lab2-work`, поэтому в конце пути присутствует и она.
- `&&` связывает шаги: следующий выполняется только при успешном завершении предыдущего. Копируй блок целиком; так при ошибке создания папки распаковка не начнётся.

Если `mkdir ~/labs/nbody-defense` сообщает `File exists`, остановись перед распаковкой: возможно, папка уже подготовлена. Посмотри её содержимое и перейди в существующий проект. Для новой копии выбери другое имя папки и используй его в последующих путях. Не смешивай старую и новую версии распаковкой поверх без проверки.

Проект лучше держать в домашней папке Linux. Архив в `C:\lab` служит для переноса; сборка и запись CSV выполняются уже в файловой системе Linux.

### 4.4. Убедиться, что это папка проекта

```bash
pwd
ls
```

`pwd` показывает текущую папку. Ожидаемый конец пути:

```text
/labs/nbody-defense/Lab2-work
```

В `ls` должны быть видны `Makefile`, `README.md`, `REPORT.md`, C/H-файлы и папки `examples`, `tools`, `measurements_windows11`.

Файл сборки называется именно **`Makefile`**, без `.txt`. В Linux регистр букв важен.

Если забыл, куда положил проект, можно поискать основной C-файл:

```bash
find ~ -maxdepth 6 -type f -name nbody_serial.c -print
```

Найденный путь заканчивается `/nbody_serial.c`. Для команды `cd` нужна папка перед этим именем файла.

## 6. Показать входные данные

В Ubuntu:

```bash
cat examples/two_bodies.txt
```

Ожидаемый вывод:

```text
2
1e12 -10 0 0 0 -0.8 0
1e12 10 0 0 0 0.8 0
```

Объяснение:

- Первая строка `2` — число тел.
- У каждого тела семь чисел: `mass x y z vx vy vz`.
- `1e12` — масса 10¹² кг.
- Начальные x равны −10 и +10 м.
- По y первое тело движется со скоростью −0.8 м/с, второе — +0.8 м/с.
- z и vz равны нулю, поэтому этот вход плоский; сам код рассчитывает силы в 3D.

Что сказать:

> Обе версии получат один и тот же файл. Это два тела одинаковой массы с заданными начальными координатами и скоростями.

После сборки:

```bash
ls -l nbody_serial nbody_pthreads
```

Что сказать:

> Makefile собирает два исполняемых файла. У каждой версии свой main, а физические формулы и ввод-вывод общие — в nbody.c.

## 8. Запустить последовательную программу

```bash
./nbody_serial 10 examples/two_bodies.txt 0.01 serial.csv
```

Аргументы:

| Часть команды | Смысл |
|---|---|
| `./nbody_serial` | Запустить собранную последовательную программу из текущей папки |
| `10` | Просчитать 10 секунд модельного времени |
| `examples/two_bodies.txt` | Прочитать начальные данные двух тел |
| `0.01` | Использовать шаг dt=0.01 секунды |
| `serial.csv` | Сохранить траекторию в этот файл |

Пример структуры вывода, где вместо многоточий будут настоящие числа:

```text
Bodies = 2, steps = 1000
Compute time = ... seconds
Total time (with CSV) = ... seconds
```

Нужно увидеть `Bodies = 2` и `steps = 1000`. Конкретные времена зависят от текущего запуска и компьютера.

Что сказать:

> Это последовательная версия. Она сделала 1000 шагов до модельного времени 10 секунд. Compute time показывает вычислительные интервалы без CSV, а Total time — моделирование с записью состояний и закрытием файла.

Число `10` в команде не означает, что программа обязана работать десять реальных секунд.

## 9. Запустить параллельную программу на тех же данных

```bash
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel.csv 4
```

Здесь вход, конечное время и шаг те же. Выход другой — `parallel.csv`. Последний аргумент `4` задаёт **четыре рабочих потока**; главный поток существует отдельно.

Ожидаемая структура вывода:

```text
Bodies = 2, threads = 4, steps = 1000
Compute time (with barriers) = ... seconds
Total time (with threads and CSV) = ... seconds
```

Что сказать:

> Теперь тот же расчёт выполняется четырьмя рабочими потоками. Время Compute включает ожидание барьеров. На двух телах накладные расходы могут сделать эту версию медленнее; здесь я показываю ход расчёта и согласованность результатов. Производительность большой задачи сохранена отдельно в отчёте.

Для сравнения сохраняй одинаковые tend, dt, вход и формат. Если изменить их только у одной версии, различие файлов уже не будет означать ошибку распараллеливания.

## 10. Сравнить последовательный и параллельный CSV

```bash
python3 tools/compare_csv.py serial.csv parallel.csv
```

Ожидается строка вида:

```text
PASS: 5005 values, max_abs=0, max_scaled=0
```

В этом примере при проверке все значения совпали. В общем случае допускаются малые различия в пределах правила сравнения.

Объяснение:

- `PASS` означает, что структура и числовые значения согласованы по правилам утилиты.
- `5005 values` — сравнили 1001 состояние по пять чисел: время и x,y двух тел.
- `max_abs` — самое большое абсолютное отличие.
- `max_scaled` — самое большое отличие, делённое на `1 + |ожидаемое значение|`; это показатель, сохранённый для описания расхождений.
- Само условие допуска для каждой ячейки: `|a−b| ≤ 1e−10 + 1e−10·|a|`, где a из первого файла.

Что сказать:

> Утилита сравнила все моменты времени и все записанные координаты, а не только последнее состояние. Сравнение использует допуск из-за арифметики double. Оно подтверждает согласованность этих двух результатов.

Python здесь читает готовые CSV. Физический расчёт и измерение интервалов выполняются внутри C-программ.

## 14. Показать свои сохранённые результаты производительности

Для начала достаточно открыть сводный CSV:

```bash
cat measurements_windows11/summary.csv
```

Если нужен удобный вывод в виде компактной таблицы, скопируй **весь следующий блок**, включая завершающую строку `PY`, в Ubuntu:

```bash
python3 - <<'PY'
import csv

print(f'{"N":>5} {"variant":<9} {"P":>2} {"Compute, s":>11} {"S":>7} {"E, %":>7}')
with open('measurements_windows11/summary.csv', newline='') as file:
    for row in csv.DictReader(file):
        mean = float(row['compute_mean'])
        speedup = '-' if row['mode'] == 'serial' else f"{float(row['speedup']):.3f}"
        efficiency = '-' if row['mode'] == 'serial' else f"{100 * float(row['efficiency']):.1f}"
        print(f"{row['N']:>5} {row['mode']:<9} {row['P']:>2} {mean:11.6f} {speedup:>7} {efficiency:>7}")
PY
```

Это только просмотр существующего CSV с форматированием. Команда не выполняет новое моделирование и не меняет файлы. Вспомогательная строка `PY` завершает многострочную команду, а не является именем программы.

Что сказать:

> Здесь сохранена исходная серия на моём ноутбуке. При 2048 телах и восьми рабочих среднее вычислительное время около 0.140641 секунды против 0.609731 у последовательной версии. Ускорение около 4.34, эффективность 54.2%. Для 128 тел устойчивый выигрыш не установлен.

Полный отчёт с характеристиками ноутбука и условиями измерения:

<https://github.com/Artem4ic/Lab2/blob/work/REPORT.md>

Исходные попытки находятся в `raw_times.csv`, сводка — в `summary.csv`, журнал сопоставления — в `comparisons.csv`. Все три файла лежат в `measurements_windows11`.

Числа на экране после короткого примера двух тел — текущий запуск другой нагрузки. Их нельзя выдавать за времена серии N=128/2048 из отчёта.

## 15. Если преподаватель попросит заново выполнить серию замеров

Перед серией подключи питание и закрой тяжёлые приложения. Не меняй условия между конфигурациями.

Выполни следующий блок из папки проекта. Первая строка создаёт новую папку со случайным окончанием имени; вторая запускается только при успешном создании:

```bash
nbody_run_dir=$(mktemp -d "$PWD/measurements_defense_XXXXXX") &&
python3 tools/benchmark.py --out "$nbody_run_dir" --sizes 128 2048 --threads 1 2 4 8 --repeats 5
```

- `--sizes 128 2048` — два размера задачи.
- `--threads 1 2 4 8` — число рабочих потоков в параллельной версии; последовательная версия добавляется отдельно.
- `--repeats 5` — пять измеряемых повторов.
- Один прогрев каждой конфигурации скрипт делает сам.
- Внутри скрипта используются tend=1, dt=0.0625 и формат xyz.

Всего выполняется 60 запусков C-программ: 10 прогревов и 50 измеряемых запусков. Основная статистика — арифметическое среднее; отдельно сохраняются разброс, минимум и максимум.

Дождись финального сообщения:

```text
All comparisons PASS; results: ...
```

В указанной новой папке будут `raw_times.csv`, `summary.csv`, `comparisons.csv`, входы и текущие траектории. 40 записей журнала сравнивают parallel с serial, ещё 10 — serial со своей копией.

Папка `measurements_windows11` содержит результаты, по которым написан отчёт. Приведённая команда пишет новую серию отдельно. Повторная серия может дать другие времена из-за текущей нагрузки и состояния ноутбука.

Расположение часов: `GET_TIME` из `timer.h` используется внутри C. Python запускает программы, читает уже выведенные времена, сравнивает CSV и считает статистику.

## 16. Если нужно показать среду запуска

В Ubuntu:

```bash
uname -m
nproc
gcc --version
python3 --version
```

- `uname -m` показывает архитектуру, например x86_64.
- `nproc` показывает число доступных процессоров в этой среде, а не доказанное число физических ядер ноутбука.
- Остальные команды показывают текущие версии инструментов.

При необходимости модель CPU можно посмотреть в отдельном **PowerShell Windows**:

```powershell
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors
```

Один ноутбук и несколько N/P — разные конфигурации, а не несколько аппаратных архитектур.

## 18. Если WSL ещё не установлен

Этот раздел нужен для подготовки ноутбука заранее.

1. В Windows найди PowerShell.
2. Выбери **Запуск от имени администратора**.
3. Выполни:

```powershell
wsl --install -d Ubuntu
```

4. Перезагрузи Windows, если установщик этого требует.
5. Открой Ubuntu из «Пуска» и заверши первичную настройку.
6. Создай Linux-имя пользователя и пароль. Во время набора пароля символы не отображаются.
7. В PowerShell проверь:

```powershell
wsl -l -v
```

Если у уже установленного дистрибутива показана VERSION 1, преобразование в WSL 2 выполняется заранее. Для имени Ubuntu:

```powershell
wsl --set-version Ubuntu 2
```

Затем возвращайся к установке GCC, make, Python и unzip в разделе 3.

Официальная инструкция Microsoft:

<https://learn.microsoft.com/en-us/windows/wsl/install>

## 19. Что делать при типичных затруднениях

| Сообщение или ситуация | Что сделать |
|---|---|
| PowerShell не понимает `make`, `sudo` или `./nbody_serial` | Открой Ubuntu; команды сборки и запуска выполняются там. |
| WSL не находит `Ubuntu` | В PowerShell выполни `wsl -l -v` и используй точное имя из списка. |
| `cd: No such file or directory` | Проверь путь, имя корневой папки ZIP и свою текущую папку через `pwd`, `ls`. Для поиска исходника используй команду из раздела 4. |
| `make: command not found` или `gcc: command not found` | В Ubuntu заранее установи `build-essential`. |
| `make: No targets specified and no makefile found` | Перейди в папку с исходниками и проверь, что файл называется `Makefile`, без `.txt`. |
| `python3: command not found` | В Ubuntu установи `python3`. |
| `./nbody_serial: No such file or directory` | Из папки проекта выполни `make`. |
| Не найден `examples/two_bodies.txt` | В командной строке нужна папка проекта, а в архиве должна присутствовать `examples`. |
| `Permission denied` при запуске скопированного готового файла | Собери программы в Linux заново: `make clean`, затем `make`. |
| `Different CSV headers` или `Different CSV sizes` | Запусти обе версии на одинаковых входе, tend, dt и формате; не смешивай xy и xyz. |
| Параллельный пример двух тел медленнее | Это допустимо: работа мала, а потоки и барьеры добавляют расходы. Для производительности используй сохранённую большую серию. |
| `pthread_create` сообщает об ошибке | Попробуй меньше рабочих потоков и закрой тяжёлые процессы. |
| `Zero or non-finite distance` | Проверь исходные данные и шаг: в момент вычисления сил расстояние стало нулевым или неконечным. Столкновения в модели не обрабатываются. |
| Терминал показывает `>` после начала многострочной команды | Обычно он ждёт продолжение блока. Заверши его полностью, а для отмены нажми Ctrl + C. |
| Нужно остановить долгий запуск | Нажми Ctrl + C; после прерывания серия может остаться незавершённой. |

## 20. Короткая последовательность, которую удобно держать перед глазами

**Windows:** Пуск → Ubuntu. Либо PowerShell: `wsl -l -v`, затем `wsl -d Ubuntu` с точным именем дистрибутива.

**Ubuntu, если папка подготовлена по этой инструкции:**

```bash
cd ~/labs/nbody-defense/Lab2-work

python3 tools/compare_csv.py serial.csv parallel.csv
head -n 5 serial.csv
tail -n 1 serial.csv
wc -l serial.csv
```

Три ожидаемых ориентира: **1000 шагов**, **PASS и 5005 значений**, **1002 строки CSV**.

После этого покажи второй слайд презентации или сводку сохранённых замеров и объясни: на 2048 телах восемь рабочих дали ускорение около 4.34 и эффективность 54.2%, а на 128 телах устойчивого выигрыша не получилось.

Если терминал больше не нужен, команда `exit` завершит текущую Linux-сессию. Во время показа можно просто оставить окно открытым.
