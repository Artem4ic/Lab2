Я выполнял задачу номер два — моделирование гравитационного движения N тел. Реализованы последовательная и параллельная версии на C с POSIX Threads. Программа получает массы, координаты и скорости тел, рассчитывает движение в трёх измерениях и сохраняет траектории в CSV.

Подготовка начинается с Get_options: она разбирает аргументы запуска и проверяет параметры. Read_bodies загружает начальные данные и проверяет массы, координаты и скорости. На каждом шаге Next_time выбирает следующий момент модельного времени; последний шаг при необходимости сокращается.

В последовательной версии Compute_forces обходит пары тел. Для каждой пары общая функция Pair_force рассчитывает силу по закону всемирного тяготения. Учитываются только пары i меньше j: одна сила добавляется первому телу и вычитается у второго. Update_body выполняет шаг явного Эйлера: сначала изменяет координаты по старой скорости, затем обновляет скорость. Write_state записывает время и координаты в CSV.

В параллельной версии pthread_create создаёт работников перед циклом моделирования, а их основная работа находится в Thread_work. Пары распределяются циклически; каждый работник накапливает силы в личном массиве, чтобы избежать одновременной записи в общую сумму.

Wait_barrier синхронизирует участников. За обычный шаг один барьер проходится трижды: старт, готовность сил и готовность новых состояний. Между вторым и третьим проходами работники собирают частичные силы и вызывают Update_body для непересекающихся диапазонов тел. Главный поток записывает результат через Write_state, а после завершения ожидает работников через pthread_join.

Макрос GET_TIME из timer.h измеряет интервалы внутри C-программы. Для ускорения используется вычислительное время с барьерами, но без записи CSV. Python организует повторные запуски: generate создаёт входные данные, compare сопоставляет траектории с допуском, а основной код benchmark.py собирает времена и статистику.

Замеры выполнены на Intel Core i5-13420H, в Ubuntu под WSL 2. Сравнивались 128 и 2048 тел при одном, двух, четырёх и восьми рабочих потоках. Для каждой конфигурации — один прогрев и пять измерений; использовано среднее. При конечном времени одна секунда и шаге 0,0625 получилось 16 шагов.

Для 2048 тел на восьми потоках ускорение составило около 4,34 раза, эффективность — 54,2 процента. Для 128 тел устойчивого выигрыша нет из-за накладных расходов. Метод Эйлера остаётся приближённым, поэтому точность зависит от шага; столкновения тел не моделируются.
