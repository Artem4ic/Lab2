## 1. Постановка задачи и принятые решения

Решается задача № 2 из файла `lab1_pthreads.pdf` — «Лабораторная работа
номер 1» от 27 сентября 2026 года, раздел 1, страницы 1–2.
Справочные формулы приведены в разделе 2.2 задания, страницы 3–5.

Требуется по массам, начальным положениям и скоростям N материальных
точек найти их траектории на интервале от 0 до tend. Входной файл содержит
число тел и по семь чисел для каждого тела: массу, x,y,z,vx,vy,vz.
Результат записывается в CSV, одна строка на момент времени.

Использован явный метод Эйлера первого порядка из методических материалов.
Шаг dt выбирается при запуске. Система единиц — СИ,
гравитационная постоянная G=6.67430·10⁻¹¹ м³/(кг·с²).

Условие даёт трёхмерный вход, но двумерные формулы и пример CSV.
В реализации принят 3D-расчёт; по умолчанию выводится xy-проекция
в формате задания, дополнительный режим xyz сохраняет все координаты.
Эксперимент проведён в режиме xyz. Начальное состояние t=0 сохраняется;
последний шаг при необходимости сокращается до tend.

### Входные данные, выход и состав программы

В первой строке входного файла задаётся положительное целое число N.
Далее для каждого тела записываются `mass x y z vx vy vz`. Массы должны
быть положительными, все числовые значения — конечными. Требуются
`tend >= 0` и `dt > 0`. При совпадении положений во время вычисления силы
программа сообщает об ошибке: в модели точечных масс нет смягчения силы.

Интерфейс программ:

```text
./nbody_serial tend input.txt [dt [output.csv [xy|xyz]]]
./nbody_pthreads tend input.txt [dt [output.csv [threads [xy|xyz]]]]
```

По умолчанию используются `dt=0.01`, файл `trajectory.csv`, формат `xy`
и два рабочих потока для параллельной версии. Допустимо от 1 до 1024
рабочих потоков. При `tend=0` записывается только начальное состояние.
CSV содержит заголовок `t,x1,y1,...` или `t,x1,y1,z1,...` и координаты
всех тел в каждый сохранённый момент времени; массы и скорости в CSV
не записываются. Выходной файл открывается с перезаписью, поэтому его
имя должно отличаться от входного файла и существующих важных файлов.

## 2. Математическая модель и последовательный алгоритм

Движение каждого тела описывается уравнением
`m_i · d²r_i/dt² = F_i` — формула (4) в задании. Для численного решения
оно записывается как система первого порядка:
`dr_i/dt = v_i`, `dv_i/dt = F_i/m_i`.

Для пары i,j сила на i со стороны j:

Fij = G·mi·mj·(rj−ri)/|rj−ri|³.

Суммарная сила Fi получается сложением вкладов остальных тел.
Третий закон Ньютона даёт Fji=−Fij. Поэтому перебираются только i<j:
к одному накопителю прибавляется сила, из другого вычитается.
За шаг выполняется N(N−1)/2 расчётов взаимодействия.

Порядок шага:

1. Обнулить массив сил.
2. Рассчитать все взаимодействия по неизменяемым старым положениям.
3. Для каждого тела выполнить r_new=r_old+v_old·h.
4. Обновить скорость: v_new=v_old+(F_old/m)·h.
5. Записать новое состояние в CSV.

Пункты 3 и 4 выполняются для каждого тела функцией Update_body после
завершения всего расчёта сил. Старые скорости используются для положения.
Это соответствует формулам (8) раздела 2.2.2 задания.
Сложность одного шага O(N²), дополнительная память O(N).

## 3. Параллельная реализация

Используются POSIX Threads в одном процессе с общей памятью.
Каждому потоку выделяется частный массив сил на N тел.
Строки верхнего треугольника пар распределяются циклически:
i=rank, rank+P, rank+2P, ...; для каждого i перебирается j>i.
Таким образом, каждая пара обрабатывается одним потоком, а противоположные
вклады записываются в его частный массив без блокировок на каждой паре.

После завершения сил выполняется барьер. Далее потоки суммируют
local_forces[rank][i] по всем rank для закреплённых за ними тел и обновляют
непересекающиеся диапазоны. Границы диапазона: N·rank/P и N·(rank+1)/P.
После следующего барьера главный поток записывает CSV, рабочие ждут начала
следующего шага. Всего три барьерные встречи на шаг, включая стартовую.

Потоки создаются один раз. Главный поток участвует в барьерах, но не считает
пары. Мьютекс и условная переменная используются в стартовом протоколе,
чтобы корректно обрабатывать неполное создание набора потоков.

Суммарная работа на шаг O(N²+PN), дополнительная память O(PN).
Частные массивы сил занимают примерно 24PN байт при 8-байтовом double;
к ним добавляются состояния тел и служебные структуры потоков.
Объединение вкладов и синхронизация ограничивают масштабирование.
Циклическая раздача приближённо выравнивает нагрузку, но не гарантирует
равенство числа пар каждого потока. На разных P меняется порядок суммирования
double, поэтому возможны небольшие численные отличия.

## 4. Проверка корректности

На этапе разработки пройдены пять групп автоматических тестов:

- равномерное движение одного тела в трёх измерениях;
- две массы: аналитический результат первых двух шагов, знак силы,
  использование старой скорости, положение центра масс;
- случайные 3D-системы для разных N и P, включая N, не делящееся на P, и P>N;
- нулевое tend, укороченный последний шаг, формат xy;
- неверные аргументы, массы, числа, неполный вход, совпадающие положения.

Независимый Python-эталон считает ускорения по всем соседям каждого тела,
не используя общие C-функции. Проверки запускаются командой `make test`;
исходный код тестов включён в проект. Отдельный журнал `make test`
с ноутбука не приложен.

В журнале эксперимента сохранены 50 записей проверки CSV измеряемых
запусков. Из них 40 сравнивают параллельную и последовательную версии:
проверяются все времена и координаты xyz всех тел, всего 2 220 200
числовых значений. Остальные 10 записей относятся к последовательным
запускам: скрипт сначала копирует их результат в эталон, затем сравнивает
с этой же копией. Такие самосравнения не проверяют повторяемость или
корректность последовательной версии. С учётом этих записей журнал
содержит 2 775 250 сопоставлений числовых значений.
Для каждого значения применялось |a−b|≤10⁻¹⁰+10⁻¹⁰·|a|,
где a — результат последовательного расчёта.
Максимальное абсолютное отличие составило 4.336808689942018·10⁻¹⁹.
Все записи журнала имеют статус PASS. Это совпадение реализаций на данных тестах,
а не доказательство физической точности любой траектории.

### Параметры эксперимента и статистика

Использовались N=128 и N=2048; tend=1, dt=0.0625 — ровно 16 шагов.
Положения заданы на трёхмерной сетке с расстоянием 1000 м, массы
псевдослучайны в диапазоне 10¹⁰–10¹² кг, компоненты скорости от −1 до 1 м/с.
Генератор Python имеет фиксированные seed=20261015+N.
Проверены последовательный вариант и параллельный вариант с P=1,2,4,8
при одном и том же входе для каждого N. Главный поток управляет расчётом
и выводом; число P относится только к рабочим потокам.
Для каждой конфигурации сначала выполнен один прогревочный запуск,
не включённый в статистику, затем пять измеряемых запусков.
Внутри каждого раунда порядок конфигураций перемешивался с фиксированным
seed=71. Запуски выполнялись последовательно, без конкурирующих процессов
из этой серии. Фоновая нагрузка Windows и планирование WSL могли влиять на измерения.
Итого проверены 10 конфигураций, выполнены 10 прогревочных и
50 измеряемых запусков. В каждом запуске записывается 17 состояний
(начальное и 16 шагов). В одном CSV для N=128 содержится 6545 числовых
значений, для N=2048 — 104465, без учёта заголовка.

Основной показатель — арифметическое среднее из пяти запусков.
Сырые времена, минимум, максимум и выборочное стандартное отклонение
сохранены в CSV папки `measurements_windows11/` и приведены ниже.
Выбросы не удалялись. У малой задачи заметен шум, поэтому
не следует ранжировать конфигурации по незначительным отличиям.

Для пяти измерений t₁,…,t₅ вычисляются среднее
T=(t₁+…+t₅)/5 и выборочное стандартное отклонение
s=√(Σ(tᵢ−T)²/4). Ускорение S=Tserial/Tparallel и эффективность
E=S/P рассчитываются по средним вычислительным временам;
в таблицах эффективность показана в процентах (100E).

Время измеряется GET_TIME преподавателя на основе gettimeofday:

- Compute time — сумма интервалов расчёта каждого шага; в параллельной версии
  включает три барьера, объединение и обновление. Не включает создание/join,
  чтение входа, выделение памяти и CSV.
- Total time — моделирование с CSV и его закрытием; для параллельной версии
  включает создание/join. Не включает чтение входа, выделение памяти,
  открытие CSV и запись его заголовка: они выполнены до начала таймера.

gettimeofday не монотонен; для коротких интервалов относительная ошибка
выше. Здесь он сохранён ради соответствия коду преподавателя.

### Анализ результатов

Для N=128 последовательная версия занимает в среднем 2.328 мс.
На двух потоках среднее равно 2.291 мс, то есть выигрыш около 0.037 мс
(1.6%), тогда как стандартное отклонение параллельных запусков 0.210 мс.
По этой серии нельзя утверждать устойчивое ускорение на двух потоках.
Для P=4 и P=8 средние времена выросли до 3.454 и 4.499 мс.
Это согласуется с преобладанием накладных расходов над выигрышем от
распараллеливания малой задачи, но отдельный вклад каждой причины
без профилирования не измерен.

Для N=2048 последовательная версия занимает 0.609731 с.
На P=2 получено 0.325926 с, S=1.871, E=93.5%;
на P=4 — 0.186292 с, S=3.273, E=81.8%;
на P=8 — 0.140641 с, S=4.335, E=54.2%.
Восемь потоков дают наименьшее среднее время среди проверенных вариантов,
а два потока — наибольшую эффективность среди P=2,4,8.
Это не доказательство оптимальности восьми потоков для других N и P:
например, 12 потоков в этой серии не проверялись.

Для N=2048 на четырёх потоках стандартное отклонение составляет около
10% среднего времени, на восьми — около 1.8%. Все пять значений включены
в статистику, минимумы и максимумы сохранены в summary.csv.
На одном рабочем потоке параллельная версия немного медленнее отдельной
последовательной: 0.628472 против 0.609731 с. Разные пути выполнения,
синхронизация и системные условия могут объяснять эту разницу;
изолированные накладные расходы отдельно не измерялись.

С учётом CSV средние времена N=2048 составляют 0.634265 с последовательно
и 0.166475 с на восьми потоках. Ускорение полного измеряемого участка
равно примерно 3.81×, тогда как ускорение вычислительной части — 4.34×.
Это два разных показателя, их не следует смешивать.

Отклонение от линейного ускорения согласуется с расходами барьеров,
объединения, доступа к памяти, дисбалансом и планированием потоков.
Гибридная архитектура CPU и виртуализация также могут влиять, но
по приложенным данным нельзя количественно разделить эти факторы.

## 7. Вывод и ограничения

Реализованы последовательный и параллельный расчёты с одинаковой схемой
Эйлера и использованием третьего закона Ньютона. Разделение вычисления
сил и обновления состояния сохраняет единый временной слой. Частные
накопители устраняют необходимость блокировки на каждом взаимодействии.
В тестах результаты совпали в пределах допуска. На системе из 2048 тел
на ноутбуке получено ускорение до 4.34× по вычислительному времени
среди проверенных вариантов. Для 128 тел устойчивый выигрыш не установлен.

Метод Эйлера не обеспечивает точного сохранения энергии и может быть
неустойчивым на больших временах и при тесных сближениях. Совпадающие
положения приводят к ошибке, столкновения не моделируются. Изменение dt
и исследование сходимости необходимы для обоснования физической точности
конкретного эксперимента. Выводы о производительности относятся только
к указанным входным данным, компилятору и среде.

## 8. Воспроизведение

```bash
make -B
make test
python3 tools/benchmark.py --out measurements_new
```

Команда использует N=128,2048, P=1,2,4,8 и пять повторов по умолчанию;
эквивалентный явный вызов:

```bash
python3 tools/benchmark.py --out measurements_new --sizes 128 2048 --threads 1 2 4 8 --repeats 5
```

Используйте новую папку: скрипт перезаписывает результаты при повторном
использовании пути. Перед замерами необходимо выполнить `make`:
скрипт запускает готовые программы, сам их не собирает.
Он создаёт входы, траектории последних запусков каждой конфигурации,
сырые времена, сравнения и сводку; траектории каждого отдельного повтора
не сохраняются. В комплекте старой серии `measurements_windows11/`
присутствуют только метаданные и журналы, без исходных входов и траекторий.
Одинаковые входы можно заново сгенерировать скриптом с фиксированными seed;
времена нового эксперимента будут зависеть от среды и нагрузки.

В Linux или Ubuntu в WSL нужны GCC, GNU Make, POSIX Threads и Python 3.
Сторонние Python-пакеты не используются. Отдельное сравнение готовых
траекторий выполняется так:

```bash
./nbody_serial 1 examples/two_bodies.txt 0.0625 serial.csv xyz
./nbody_pthreads 1 examples/two_bodies.txt 0.0625 parallel.csv 4 xyz
python3 tools/compare_csv.py serial.csv parallel.csv
```

Объяснение к защите — `DEFENSE.md`, инструкция Windows 11 —
`WINDOWS11_WSL2.md`. Исходные материалы задания:
lab1_pthreads.pdf; стиль Pthreads и замера времени — pth_ll_rwl.c и timer.h.

## 9. Проверка присланных файлов

Повторно пересчитаны среднее, выборочное стандартное отклонение, минимум,
максимум, среднее полное время, ускорение и эффективность по raw_times.csv.
Все показатели совпали с summary.csv с относительным допуском 10⁻¹².
Для каждой из 10 конфигураций есть ровно пять повторов с номерами 1–5.
Наборы конфигураций и повторов в comparisons.csv и raw_times.csv совпадают.
Все вычислительные времена положительны, полные времена не меньше
вычислительных. Все 50 записей `comparisons.csv` имеют статус PASS;
из них 40 являются сравнениями параллельного расчёта с последовательным.
Предоставленные журналы согласованы между собой. Полные траектории
ноутбука не приложены: сравнения анализировались по сохранённому журналу,
самостоятельное повторное сравнение этих траекторий здесь не выполнялось.
