## Выступление на 2–3 минуты

Текст рассчитан примерно на 2,5–3 минуты с короткими паузами. Команды ниже произносимое время не увеличивают.

**Слайд 1:** первые два абзаца.

Я выполнял задачу номер два — моделирование гравитационного движения N тел. На вход подаются массы, начальные координаты и скорости тел, а также конечное время. Программа рассчитывает движение в трёх измерениях и сохраняет траектории в CSV.

Силы рассчитываются по закону всемирного тяготения. Для движения используется явный метод Эйлера. На каждом шаге сначала находятся силы по старым координатам, затем обновляются положения и скорости. Координаты обязательно изменяются по старой скорости. Каждая пара тел рассматривается только один раз: сила прибавляется одному телу и вычитается у другого. Это использование третьего закона Ньютона уменьшает число вычислений взаимодействий вдвое.

**Переключить на слайд 2.**

Реализованы две версии на C: последовательная и параллельная с POSIX Threads. В параллельной версии рабочие потоки создаются один раз на всё моделирование. Строки перебора пар распределяются между ними циклически. Каждый поток сначала накапливает силы в своём массиве, поэтому при вычислении пар нет одновременной записи в общую сумму.

Один объект барьера используется три раза за шаг. Первый проход разрешает начать расчёт, второй означает готовность всех сил, третий — готовность новых состояний. Между вторым и третьим проходами потоки складывают частичные силы и обновляют непересекающиеся диапазоны тел. После этого главный поток записывает CSV. Результаты двух версий сравниваются с численным допуском.

Время измеряется внутри C-программ через timer.h. Отдельно выводится время вычислений и время с записью CSV. Для ускорения используется вычислительное время, которое в параллельной версии включает барьеры. Python нужен для повторных запусков, сравнения траекторий и расчёта статистики.

Замеры выполнены на ноутбуке с Intel Core i5-13420H, в Ubuntu под WSL 2 на Windows 11. Сравнивались 128 и 2048 тел, последовательная версия и один, два, четыре и восемь рабочих потоков. Для каждой конфигурации выполнен один прогрев и пять измерений; в отчёте приведено среднее. Параметры серии: конечное время одна секунда, шаг 0,0625 секунды, то есть 16 шагов.

Для 2048 тел на восьми потоках получено ускорение примерно в 4,34 раза и эффективность 54,2 процента. Для 128 тел устойчивого выигрыша нет: расходы на синхронизацию могут перекрывать пользу распараллеливания. Таким образом, среди проверенных вариантов распараллеливание полезно на большой задаче. Метод Эйлера остаётся приближённым: для большей точности нужно уменьшать шаг, а столкновения тел здесь не моделируются.

## Команды — отдельно от времени выступления

Команды выполняются в Linux или Ubuntu внутри WSL, из папки проекта. Показ команд и ожидание их выполнения не входят в 2–3 минуты выступления.

В текущей облачной среде сначала перейди в проект:

```bash
cd /workspace/Lab2
```

Если проект распакован на твоём ноутбуке, открой терминал в его папке; путь `/workspace/Lab2` относится только к облачной среде.

**1. Собрать обе программы:**

```bash
make
```

**2. Последовательный расчёт: 10 модельных секунд, шаг 0.01, два тела:**

```bash
./nbody_serial 10 examples/two_bodies.txt 0.01 serial.csv
```

**3. Тот же расчёт четырьмя рабочими потоками:**

```bash
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel.csv 4
```

У обеих программ должно быть `steps = 1000`. Число 10 — модельное время; число 4 — рабочие потоки. Это не число тел и не число секунд работы компьютера.

**4. Сравнить два результата:**

```bash
python3 tools/compare_csv.py serial.csv parallel.csv
```

Ожидается `PASS: 5005 values`. Максимальные отличия должны укладываться в допуск. В данном примере при проверке обеих версий все значения совпали.

**5. Показать начало, конец и число строк траектории:**

```bash
head -n 5 serial.csv
tail -n 1 serial.csv
wc -l serial.csv
```

Ожидается заголовок `t,x1,y1,x2,y2`, последний момент времени 10 и всего 1002 строки: заголовок плюс 1001 состояние, включая t=0.

**6. При необходимости сохранить все три координаты:**

```bash
./nbody_serial 10 examples/two_bodies.txt 0.01 serial3d.csv xyz
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel3d.csv 4 xyz
python3 tools/compare_csv.py serial3d.csv parallel3d.csv
```

В этом режиме заголовок `t,x1,y1,z1,x2,y2,z2`, а утилита сравнит 7007 чисел. Физика остаётся трёхмерной и в режиме xy; xyz меняет только вывод.

**7. Повторить серию производительности отдельно от короткой демонстрации:**

```bash
python3 tools/benchmark.py --out measurements_defense --sizes 128 2048 --threads 1 2 4 8 --repeats 5
```

Выбирай новую выходную папку для каждой серии: существующие файлы по тому же пути будут перезаписаны. Сохранённую папку `measurements_windows11` не перезаписывай. Новые времена относятся к машине текущего запуска; облачные результаты не заменяют исходные результаты ноутбука в отчёте.

Скрипт использует tend=1, dt=0.0625 и xyz. Получится 10 конфигураций: 10 прогревов и 50 измеряемых запусков. В журнале будет 40 сравнений параллельной версии с последовательной и 10 самосравнений serial с копией.

**8. При необходимости собрать напрямую, без Make:**

```bash
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic nbody_serial.c nbody.c -lm -o nbody_serial
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic -pthread nbody_pthreads.c nbody.c -lm -o nbody_pthreads
```

**9. Очистить только собранные программы:**

```bash
make clean
```

## Короткая памятка для вопросов

- Сила: Fij = G·mi·mj·(rj−ri)/|rj−ri|³, G = 6.67430·10⁻¹¹. Куб учитывает умножение на вектор направления длины r; величина силы убывает как 1/r².
- Число пар за шаг: N(N−1)/2. Противоположны силы, а не обязательно ускорения.
- В явном Эйлере справа используются старые положения и старые скорости.
- У каждого рабочего свой массив сил; после готовности всех вкладов выполняется их суммирование.
- Барьер один, проходов за обычный шаг три. Участников P+1, включая главный поток.
- Compute time не включает CSV и создание/join; в параллельной версии включает барьеры, обнуление, объединение сил и обновление тел.
- Total time включает запись состояний и закрытие CSV, а также создание/join в параллельной версии. Чтение входа, выделение памяти, открытие CSV и заголовок находятся до этого интервала.
- Работа serial за шаг O(N²); суммарная работа потоков O(N²+PN), дополнительная память O(PN). Это порядок роста объёма работы и памяти, а не точное число секунд.
- S = среднее T_serial / среднее T_parallel; E = S/P. Эффективность не является процентом загрузки CPU.
- Допуск CSV: |a−b| ≤ 1e−10 + 1e−10·|a|. Совпадение двух версий не доказывает отсутствие общей ошибки физической формулы.
- Приведённые замеры относятся к одному ноутбуку и архитектуре x86_64. Разные N и P — конфигурации, а не разные архитектуры.
- В отчёте сохранена исходная серия ноутбука до исправления округления времени. При её dt=0.0625 и ранее было 16 шагов; траектории после правки совпали с прежними. Эта история не подменяется новыми облачными временами.
