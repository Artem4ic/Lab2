Артём Линник · 23КНТ3

Подробный порядок показа на Windows: [от открытия WSL до запуска программ и просмотра результатов](DEFENSE_WSL_RUNBOOK.md).

## Выступление на 2–3 минуты

Текст рассчитан примерно на 2,5–3 минуты с короткими паузами. Команды ниже произносимое время не увеличивают.

**Слайд 1:** первые три абзаца.

Я выполнял задачу номер два — моделирование гравитационного движения N тел. Реализованы последовательная и параллельная версии на C с POSIX Threads. Программа получает массы, координаты и скорости тел, рассчитывает движение в трёх измерениях и сохраняет траектории в CSV.

Подготовка начинается с Get_options: она разбирает аргументы запуска и проверяет параметры. Read_bodies загружает начальные данные и проверяет массы, координаты и скорости. На каждом шаге Next_time выбирает следующий момент модельного времени; последний шаг при необходимости сокращается.

В последовательной версии Compute_forces обходит пары тел. Для каждой пары общая функция Pair_force рассчитывает силу по закону всемирного тяготения. Учитываются только пары i меньше j: одна сила добавляется первому телу и вычитается у второго. Update_body выполняет шаг явного Эйлера: сначала изменяет координаты по старой скорости, затем обновляет скорость. Write_state записывает время и координаты в CSV.

**Переключить на слайд 2.**

В параллельной версии pthread_create создаёт работников перед циклом моделирования, а их основная работа находится в Thread_work. Пары распределяются циклически; каждый работник накапливает силы в личном массиве, чтобы избежать одновременной записи в общую сумму.

Wait_barrier синхронизирует участников. За обычный шаг один барьер проходится трижды: старт, готовность сил и готовность новых состояний. Между вторым и третьим проходами работники собирают частичные силы и вызывают Update_body для непересекающихся диапазонов тел. Главный поток записывает результат через Write_state, а после завершения ожидает работников через pthread_join.

Макрос GET_TIME из timer.h измеряет интервалы внутри C-программы. Для ускорения используется вычислительное время с барьерами, но без записи CSV. Python организует повторные запуски: generate создаёт входные данные, compare сопоставляет траектории с допуском, а основной код benchmark.py собирает времена и статистику.

Замеры выполнены на Intel Core i5-13420H, в Ubuntu под WSL 2. Сравнивались 128 и 2048 тел при одном, двух, четырёх и восьми рабочих потоках. Для каждой конфигурации — один прогрев и пять измерений; использовано среднее. При конечном времени одна секунда и шаге 0,0625 получилось 16 шагов.

Для 2048 тел на восьми потоках ускорение составило около 4,34 раза, эффективность — 54,2 процента. Для 128 тел устойчивого выигрыша нет из-за накладных расходов. Метод Эйлера остаётся приближённым, поэтому точность зависит от шага; столкновения тел не моделируются.

## Команды — отдельно от времени выступления

Команды выполняются в Linux или Ubuntu внутри WSL, из папки проекта. Показ команд и ожидание их выполнения не входят в 2–3 минуты выступления.

В текущей облачной среде сначала перейди в проект:

```bash
cd /workspace/Lab2
```

Если проект распакован на твоём ноутбуке, открой терминал в его папке; путь `/workspace/Lab2` относится только к облачной среде.

**1. Собрать обе программы:**

```bash
make
```

**2. Последовательный расчёт: 10 модельных секунд, шаг 0.01, два тела:**

```bash
./nbody_serial 10 examples/two_bodies.txt 0.01 serial.csv
```

**3. Тот же расчёт четырьмя рабочими потоками:**

```bash
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel.csv 4
```

У обеих программ должно быть `steps = 1000`. Число 10 — модельное время; число 4 — рабочие потоки. Это не число тел и не число секунд работы компьютера.

**4. Сравнить два результата:**

```bash
python3 tools/compare_csv.py serial.csv parallel.csv
```

Ожидается `PASS: 5005 values`. Максимальные отличия должны укладываться в допуск. В данном примере при проверке обеих версий все значения совпали.

**5. Показать начало, конец и число строк траектории:**

```bash
head -n 5 serial.csv
tail -n 1 serial.csv
wc -l serial.csv
```

Ожидается заголовок `t,x1,y1,x2,y2`, последний момент времени 10 и всего 1002 строки: заголовок плюс 1001 состояние, включая t=0.

**6. При необходимости сохранить все три координаты:**

```bash
./nbody_serial 10 examples/two_bodies.txt 0.01 serial3d.csv xyz
./nbody_pthreads 10 examples/two_bodies.txt 0.01 parallel3d.csv 4 xyz
python3 tools/compare_csv.py serial3d.csv parallel3d.csv
```

В этом режиме заголовок `t,x1,y1,z1,x2,y2,z2`, а утилита сравнит 7007 чисел. Физика остаётся трёхмерной и в режиме xy; xyz меняет только вывод.

**7. Повторить серию производительности отдельно от короткой демонстрации:**

```bash
python3 tools/benchmark.py --out measurements_defense --sizes 128 2048 --threads 1 2 4 8 --repeats 5
```

Выбирай новую выходную папку для каждой серии: существующие файлы по тому же пути будут перезаписаны. Сохранённую папку `measurements_windows11` не перезаписывай. Новые времена относятся к машине текущего запуска; облачные результаты не заменяют исходные результаты ноутбука в отчёте.

Скрипт использует tend=1, dt=0.0625 и xyz. Получится 10 конфигураций: 10 прогревов и 50 измеряемых запусков. В журнале будет 40 сравнений параллельной версии с последовательной и 10 самосравнений serial с копией.

**8. При необходимости собрать напрямую, без Make:**

```bash
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic nbody_serial.c nbody.c -lm -o nbody_serial
gcc -O2 -std=c11 -Wall -Wextra -Wpedantic -pthread nbody_pthreads.c nbody.c -lm -o nbody_pthreads
```

**9. Очистить только собранные программы:**

```bash
make clean
```

## Короткая памятка для вопросов

- Сила: Fij = G·mi·mj·(rj−ri)/|rj−ri|³, G = 6.67430·10⁻¹¹. Куб учитывает умножение на вектор направления длины r; величина силы убывает как 1/r².
- Число пар за шаг: N(N−1)/2. Противоположны силы, а не обязательно ускорения.
- В явном Эйлере справа используются старые положения и старые скорости.
- У каждого рабочего свой массив сил; после готовности всех вкладов выполняется их суммирование.
- Барьер один, проходов за обычный шаг три. Участников P+1, включая главный поток.
- Compute time не включает CSV и создание/join; в параллельной версии включает барьеры, обнуление, объединение сил и обновление тел.
- Total time включает запись состояний и закрытие CSV, а также создание/join в параллельной версии. Чтение входа, выделение памяти, открытие CSV и заголовок находятся до этого интервала.
- Работа serial за шаг O(N²); суммарная работа потоков O(N²+PN), дополнительная память O(PN). Это порядок роста объёма работы и памяти, а не точное число секунд.
- S = среднее T_serial / среднее T_parallel; E = S/P. Эффективность не является процентом загрузки CPU.
- Допуск CSV: |a−b| ≤ 1e−10 + 1e−10·|a|. Совпадение двух версий не доказывает отсутствие общей ошибки физической формулы.
- Приведённые замеры относятся к одному ноутбуку и архитектуре x86_64. Разные N и P — конфигурации, а не разные архитектуры.
- В отчёте сохранена исходная серия ноутбука до исправления округления времени. При её dt=0.0625 и ранее было 16 шагов; траектории после правки совпали с прежними. Эта история не подменяется новыми облачными временами.


## Карта функций для дополнительных вопросов

Эта таблица — памятка, её не нужно целиком читать в основном выступлении.

| Имя | Где находится | Назначение |
|---|---|---|
| `main` | `nbody_serial.c`, `nbody_pthreads.c` | Управляет подготовкой, шагами, выводом и освобождением ресурсов своей версии. |
| `Get_options` | `nbody.c` | Разбирает аргументы запуска: tend, вход, dt, выход, число работников и формат; проверяет допустимые значения. |
| `Read_number` | `nbody.c` | Полностью преобразует строку в конечное число; отвергает неверную запись и ошибки преобразования. |
| `Usage` | `nbody.c` | Печатает формат запуска и завершает процесс с ошибкой при неверных аргументах. |
| `Allocate` | `nbody.c` | Выделяет обнулённую память через calloc, проверяя переполнение размера и успех выделения. |
| `Read_bodies` | `nbody.c` | Читает N и начальные данные тел; проверяет положительность масс, конечность чисел и отсутствие лишних данных. |
| `Open_output` | `nbody.c` | Открывает выходной CSV с перезаписью и записывает заголовок xy или xyz. |
| `Next_time` | `nbody.c` | Вычисляет следующий момент по номеру шага и dt, ограничивает его tend, учитывает округление и проверяет продвижение времени. |
| `Compute_forces` | `nbody_serial.c` | Обнуляет массив сил и последовательно обходит все пары i<j, вызывая Pair_force. |
| `Pair_force` | `nbody.c` | Возвращает трёхмерную силу, действующую на первое тело со стороны второго; проверяет расстояние и конечность результата. |
| `Add_force`, `Subtract_force` | `nbody.c` | Покомпонентно прибавляют или вычитают вектор, накапливая противоположные вклады пары. |
| `Update_body` | `nbody.c` | Выполняет явный шаг Эйлера для одного тела: координаты по старой скорости, затем скорость по силе и массе. |
| `Write_state` | `nbody.c` | Записывает одну строку с модельным временем и координатами всех тел; замечает ошибки записи. |
| `Close_output` | `nbody.c` | Закрывает CSV и проверяет ошибку, которая могла проявиться при сбросе буфера. |
| `Thread_work` | `nbody_pthreads.c` | Ждёт разрешения старта, считает назначенные пары в личный массив, собирает силы и обновляет свой диапазон тел. |
| `Wait_barrier` | `nbody_pthreads.c` | Обёртка над pthread_barrier_wait с проверкой результата; специальный успешный статус одного участника не считается ошибкой. |
| `Check_pthread` | `nbody_pthreads.c` | Обрабатывает ненулевой код ошибки Pthreads, печатает пояснение и завершает процесс. |
| `pthread_create`, `pthread_join` | Библиотека POSIX Threads | Создать рабочего и дождаться его завершения. Это библиотечные функции. |
| `GET_TIME` | `timer.h` | Макрос, а не обычная функция: вызывает gettimeofday и переводит секунды с микросекундами в double. |
| `generate` | `tools/benchmark.py` | Генерирует входную систему с фиксированным зерном; все варианты для одного N получают один вход. |
| `compare` | `tools/benchmark.py` | Сравнивает структуру двух CSV, конечность и значения ячеек с допуском; возвращает максимальные отличия и число значений. |
| `main` | `tools/benchmark.py` | Разбирает параметры серии, организует прогрев и повторы, запускает C-программы, считывает их времена и пишет три таблицы. |
| `main` | `tools/compare_csv.py` | Принимает два пути, вызывает compare и печатает итог сравнения. |
